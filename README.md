# Project Design: VLX VisionBridge

## Project Overview

VLX VisionBridge is a headless, high-performance Linux service written in Go. It aggregates multiple finite SRT/WebRTC/Media streams into a single composite live stream, broadcasted simultaneously to multiple CDNs (YouTube, Twitch, VK).

The service is designed for professional 24/7 broadcasting environments where configuration must be dynamic and resource efficiency is paramount. We are basically building a sort of obs-studio for remote VMs.

## Requirements Note

- **Hardware**: Multi-core CPU for FFmpeg processing, adequate RAM for media buffering.
- **Software**: Modern Linux distribution (e.g., Ubuntu 20.04/22.04), FFmpeg installed and accessible. Xvfb and Chromium (optional, if using overlay HTML sources).
- **Network**: High-bandwidth, low-latency network connection to handle multiple SRT/WebRTC streams and simultaneous broadcasting to multiple CDNs.

## Core Principles

- **Headless First**: Managed entirely via configuration files or DB entries.
- **Dynamic Reconfiguration**: Hot-reloading of layouts and sources without dropping the output stream (where technically possible).
- **Resource Optimization**: Sources marked as "OFF" are completely excluded from the processing pipeline.
- **Multi-Destination**: Single encoding pass with multiple output clones.

## Architecture Components

1. **Config Watcher**: Monitors `visionbridge.settings` using `fsnotify`.
2. **State Manager**: Orchestrates the current state between the Config File and SQLite.
3. **FFmpeg Engine**: A Go wrapper that generates and manages a complex subprocess for video/audio composition.
4. **Health Monitor**: Monitors CPU/RAM usage and stream stability, logging metrics to SQLite.

## Technology Stack

- **Language**: Go (Golang)
- **Processing Engine**: FFmpeg (via os/exec or CGO bindings)
- **Database**: SQLite (State persistence, Logs, Metadata)
- **Messaging (Optional)**: ZMQ for real-time filter communication with FFmpeg.

# High-Level Design (HLD)

*Note: This architecture is essentially building a headless OBS Studio tailored for remote VMs.*

## 1. System Workflow

The service initializes by reading the configuration. It builds a "Filter Graph" representing the 10 media layers alongside the Chromium overlay source.

- **Input Layer**: Handles SRT handshake, file looping, image buffers, and x11grab Chromium captures.
- **Processing Layer**: Scales, positions, and overlays inputs based on absolute integer-based pixel sizing and X/Y coordinates.
- **Output Layer**: Encodes the composite frames into H.264/AAC and pushes to the `tee` muxer.

## 2. Dynamic Layer Management

The mixer coordinates two distinct input pipelines conceptually similar to OBS Studio's "Sources" within a "Scene" (Layout):

**Standard Media Layers (`ffmpeg_source`)**: Up to 10 independent objects managed directly via FFmpeg inputs.
- **State**: `Active` | `Inactive`
- **Input Type**: `local` (folder of media), `srt`, `rtmp` (and `rtmps`), `webrtc`, `rtsp` (and `rtsps`). For `local`, folder combinations are automatically parsed (video only, image + audio, image only, audio only).
- **Media**: `Video+Audio` | `Video` | `Audio`
- **Transform**: `Size` (scale width), `X`, `Y` (Position).
- **Audio**: Configurable `Volume` per layer.

**HTML Overlays (`chromium_source`)**: An independently spawned Chromium process dynamically rendering up to 7 Z-layers, composite-captured by FFmpeg.
- Handles standard web URLs, as well as automatic HTML `<video>` / `<img>` / `<audio>` tag generation for local media.

## 3. Database Schema (SQLite)

While the `visionbridge.settings` is the primary trigger, SQLite stores:

- **Source Templates**: Reusable SRT URLs or file paths.
- **Layout Presets**: Saved configurations of the 10 layers.
- **Broadcast Logs**: Uptime, bitrate fluctuations, and error states.

## 4. Concurrency Model

Go routines are used to:

1. Manage the FFmpeg process lifecycle.
2. Listen for OS signals (SIGTERM, SIGHUP).
3. Update the DB with real-time health stats.
4. Watch for file system changes.

## 5. Specifications

The service is fully configured via the `visionbridge.settings` file (default location: `/opt/VLX_VisionBridge/etc/visionbridge.settings`).

### Global Output Settings (`output`)
Defines the final composite stream generated by the mixer.

- **`resolution`**: Target output resolution format "WxH" (e.g., `1920x1080`).
- **`fps`**: Target output framerate (e.g., `30` or `60`).
- **`video_bitrate`**: Output video bitrate (e.g., `6000k`).
- **`audio_bitrate`**: Output audio bitrate (e.g., `160k`).
- **`destinations`**: List of strings containing destination URLs to stream to (e.g., RTMP endpoints, SRT). Multiple destinations will use the `tee` muxer.

### Global Input Settings (`input`)
Defines the base canvas size for FFmpeg filtergraphs and manages the dual source types.

- **`resolution`**: Base canvas size format "WxH" (e.g., `1920x1080`).

#### Chromium Source (`chromium_source`)
Defines up to 7 distinct HTML overlay Z-layers (`Z1` to `Z7`) captured via `x11grab`.
- **`active`**: Boolean indicating whether the Chromium source is processed.
- For each sub-layer (`Z1` to `Z7`):
  - **`zX_active`**: Boolean indicating whether this Z-layer is enabled.
  - **`zX_path`**: The file path or URL for the source media (supports `.png`, `.jpg`, `.mp4`, `.webm`, `.mp3`, or generic URLs).
  - **`zX_volume`**: Audio volume percentage.
  - **`zX_width`**: Width in pixels for the HTML element.
  - **`zX_x`**: X-coordinate position.
  - **`zX_y`**: Y-coordinate position.

#### FFmpeg Source Layers (`ffmpeg_source.layers`)
Defines up to 10 standard media layers to compose the scene.

- **`id`**: Numeric ID of the layer (e.g., `0` to `9`).
- **`active`**: Boolean indicating whether this layer is processed. Set to `false` to completely exclude the source from the FFmpeg pipeline.
- **`input_type`**: The type of input source. Options:
  - `local`: Reads from a local directory specified in `input_path`. Automatically detects media combinations like video (`.mp4`, `.webm`), images + audio (`.png` and `.mp3`), images only (`.png`), or audio only (`.mp3`).
  - `srt`: Secure Reliable Transport stream.
  - `rtmp` / `rtmps`: Real-Time Messaging Protocol stream.
  - `webrtc`: WebRTC stream.
  - `rtsp` / `rtsps`: Real Time Streaming Protocol stream.
- **`input_path`**: The file path, directory path, or URL for the source media/stream depending on `input_type`.
- **`media`**: Specifies which media tracks to process. Options:
  - `Video+Audio`: Processes both tracks.
  - `Video`: Ignores audio from the source.
  - `Audio`: Ignores video from the source.
- **`size`**: Width in pixels to scale the video input.
- **`x`**: X-coordinate for positioning the video layer on the canvas.
- **`y`**: Y-coordinate for positioning the video layer on the canvas.
- **`volume`**: Audio volume percentage (e.g., `100` for 100%).

### Database Settings (`database`)
- **`dsn`**: Path to the SQLite database file (e.g., `/opt/VLX_VisionBridge/var/visionbridge.db`).
